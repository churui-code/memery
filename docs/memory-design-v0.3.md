# 持续自我与长期经历记忆 v0.3

日期：2026-10-26（Asia/Shanghai）。本文描述当前实现及能力边界，取代早期设计中的固定管家定位。

## 目标

同一个 AI 长期积累经历，形成有依据、能发展也能修正的自我认识、观点、情绪、关系认识和目标。帮助、陪伴、学习、创作或家居能力可作为技能接入，不能决定整个记忆系统只收集“对服务有用的用户偏好”。

记忆持久化与主观感受是不同问题。本实现提供可以检查的持续状态、形成原因与变化历史；不把模型表达的感情、内部情绪字段或数值衰减当作具有人的主观体验的证明。

## 保留与重做

保留 PostgreSQL、pgvector、本地中文向量、事实版本、事务提交、删除账本与恢复流程。重做对话身份与记忆组织，新增完整经历、事件轮廓与关键片段、时序回忆、自我状态和来源依赖图。不清空正式数据库，不删除用户旧记录。

`migration_003.sql` 在一次事务中增量建表，保存仍在库中的 v0.1/v0.2 消息及其角色、日期与原事实来源。旧版本已经清理的对话不可能通过迁移恢复。迁移后的助手发言只能证明当时说过这句话。

## 数据模型

| 存储 | 职责 |
|---|---|
| `memories` / `events` / `memory_evidence` | 用户明确事实、条件、版本、纠错与来源原话；`events` 是事实版本记录，不是生活经历 |
| `experiences` | 每轮成功且允许记录的完整双方发言；可选标题、摘要、重要性、人物、原话锚点、场景性质、发生时间与时间原话 |
| `experience_chunks` / `experience_jobs` | 全文分块向量及可重试租约任务；索引失败不影响原文和关键词检索 |
| `self_observations` | 按领域和稳定 key 追加版本的内部认识，保留形成原因、原话、置信度与来源 |
| `context_links` | 事实、经历、先前内部认识到派生经历/内部认识的有向来源关系；用于递归撤销 |
| `messages` | 可清理的近期会话窗口，关联永久经历 ID |

`recorded_at` 由服务端记录，`occurred_at` 由模型根据原话提出，必须附逐字可验证的 `time_quote`。时间引用真实不代表模型推算日期必然正确，原文仍是证据。未明确的事件日期不填。

经历性质为 conversation、reported、hypothetical 或 fiction，分别对应真实发生的讨论、用户转述、假设和作品。即使讨论虚构故事，也有“讨论过此作品”的真实对话经历；不能升级为现实亲历。

摘要和重要性是派生解释，锚点引用必须是当前原文的连续片段。完整原文不依赖提炼是否成功，也不依赖最多 32 项事实变更或 32 个锚点的输出限制。失败的模型请求不提交不完整轮次，明确不记录及遗忘轮次不新增档案。

## 自我发展

五类内部认识是 emotion、relationship、identity、belief、goal。每项有稳定 key、版本、内容、原因、当前原话引用和置信度；有必要时引用已实际提供的旧经历。内部认识的来源可以是当次讨论本身，以及此次读到的旧经历和当前自我状态。

同一 key 的新版本保留旧版本，不会直接覆盖旧认识。当前快照取每个 key 的最后一个版本；最新版本失效或被删时不退回以前的观点，避免“撤销新观点反而复活旧错误”。历史可以分页查看。

情绪保存原始强度与半衰期，读取时计算 `current_intensity = intensity * 2 ** (-elapsed_hours / half_life_hours)`。这是一种可解释的初始动态机制，历史原因不随衰减消失。关系和信念不使用统一好感分数，不做同样的数值衰减。

整理器被要求只在确有变化时提出内部认识，不能将“用户要求你爱我”直接当作已经形成的感情。这个语义要求由模型执行；服务端能保证来源引用和 ID 有效、结构合法、版本和事务一致，不能形式化保证所有解释都合情合理。

## 每轮流程

1. 读取有关事实、同会话近期消息、相关旧经历和当前内部状态。
2. 对“昨天/前天/今天”同时考虑记录时间与有依据的发生时间，另外保留语义结果和少量近期经历，避免把今天讲述昨天的事件漏掉。
3. M3 提出事实操作、本轮经历描述、内部变化、可选时间/关键词补充检索。
4. 本地核对引文、目标版本、已提供的来源经历 ID、时间范围及情绪字段；不允许遗忘或不记录轮次同时形成新的自我状态。
5. 执行最多四项补充检索，过滤正在纠正/删除的派生上下文，再生成回答。模型会看到拟提交的内部变化，以保持当次反应与后续状态一致。
6. 在同一事务中保存事实、完整经历、内部认识、来源边、索引任务和近期聊天，成功后返回。情绪和记忆不会在回答失败时悄悄写入。

回忆可使用全文关键词、分块语义、日期范围，原文可按 ID 展开。关键词逐块分词，避免长对话末尾的独特词被前部词数上限挤掉。长叙事使用独立的语义候选阈值（默认 0.42，可配置）；不直接沿用短事实的 0.55。阈值只是候选筛选，不能保证语义理解正确。对话中的原始经历正文预算为 20,000 字符，内部状态每类最多加载 6 项，优先匹配当前问题中的关键词，再按时间选择，避免旧观点仅因出现较早而被近期无关状态挤掉；原文超预算会标注截断。补充检索是一轮检索扩展，不是无限多步自主调查。完整历史仍在库中，检索失败不代表事件从未发生。

## 纠错、变化与删除

`correction` 表示此前记录有误：原经历保留在本地历史中，退出自动回忆；依赖它的内部认识失效。`evolution` 表示以前确实如此、现在改变：以前的经历保持可回忆，相关内部认识需要重新形成。当前事实由新版本提供，旧经历需按过去的状态理解。

来源变为 `allow_cloud=false` 时，递归撤销其派生内部状态并禁止派生档案上云。删除会清空受影响档案正文、摘要、锚点、人物及内部状态内容，清除向量，取消索引任务，并清理受影响的近期消息。来源关系只保留 ID。

来源依赖采取保守策略：模型读到过的有关事实、经历、内部状态与近期对话都建立来源边。删除一个来源可能清理整个派生轮次，即使其中含有其他内容。独立事实与经历是不同记录：删除经历/会话不自动删除独立保存的事实，删除事实则撤销其派生副本。自然语言遗忘仍用于准确定位已知事实；经历和内部认识有独立的删除接口。

独立账本新增 experience/self 类型。恢复旧备份时先迁移，再递归重放删除；晚到的向量工作检查租约和删除状态，不得把被删内容写回来。

## 长期运行与验证

经历不按 30 天自动过期，事实仍遵守明确有效期与删除要求。新备份使用经过分块认证的流式 v2 格式，避免随经历增长而把整份数据库 dump 装进内存；v1 格式保持兼容。恢复先在隔离数据库内完整认证，之后才可切换。仍需可用存储、异机备份和保管密钥，软件无法保证硬盘永不损坏。

测试覆盖迁移与原话保留、长文本尾部线索、跨会话状态、情绪衰减、形成原因、记录时间与发生时间、检索扩展、事务回滚、隐私撤销、来源递归删除与恢复重放、索引竞争、备份认证及旧格式兼容。真实模型验收使用独立安装和合成故事，不能把合成内容写入正式个人记忆。

当前自我整理由对话触发，尚无离线自主生活、自动执行目标、完整的跨经历语义知识图谱或未经交互的后台云端反思循环。这些不应被描述为已经交付的能力。长期个性与关系质量也不能由几轮测试证明，需要在此机制上持续观察和改进。
