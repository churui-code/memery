## 失败记录与修复

开发过程中发生过原文引用遗漏/抄写改字、工具协议不完整、字段类别或名称不一致、来源日期过度精确、内部状态被上下文挤出，以及瞬时连接失败。所有失败实测记录保留在 `verification-v0.4-initial/second/third.json`、`verification-encoding-v0.4-initial.json` 和 [verification-history/](verification-history/)；本次验收没有把这些失败抹除，也不把重跑后的成功称为首次全通过。

主要修复是原文单元引用与逐字核对、来源支持的日期精度、共享细节/线索类别、严格解释字段别名、实际请求成本编排、相关内部状态的上下文优先级，以及计入三次总上限的单次瞬时故障重试。引用验证、来源冲突、权限变化、限流和重评失败均不重试。

最终 pytest 和长叙述验证使用部署镜像 `sha256:b9faa58846bcff264848460b9c23289c35554d21006c4d7dc0f061ca5959b1eb`。完整向量/12 项 M3 和恢复演练使用前一验收镜像 `sha256:ca66c6ce418a1dc51d7a2217d09eccb86fccaf80171d273d6fc7f74eca6136bb`；其后只追加了原文空白保留、实验报告以实际上下文计分、严格解释字段别名与协议失败用量审计，并在最终完整 pytest、长叙述实测和部署后 HTTP 检查覆盖这些变化。没有改动召回策略、存储迁移、删除/备份或模型请求 schema。

## 重现命令与剩余边界

先启动服务，再串行执行；真实模型命令会发送冻结的合成数据并产生调用费用：

```sh
docker compose run --rm -T --no-deps api python -m pytest -q
python3 scripts/verify_memory_v4.py --real-model --full-index
python3 scripts/verify_encoding_v4.py --real-model
python3 scripts/verify.py
```

不使用真实模型时省略 `--real-model`；需要增加规模采样时在核心脚本追加 `--repeats 3`。生产与实验启动方法见 API 文档。旧版自动记忆实测报告不计为本次 v0.4 通过证明。

半衰期和唤醒阈值是工程初值；当前接口单轮输入上限为 8000 字符，必要内容超过估算预算时明确失败。持久容量受磁盘和索引成本约束；模型的事件划分、解释和回答仍可能出错，严格验证失败会拒绝整轮提交。删除继续采用保守来源依赖，可能连带删除整轮派生内容。当前情绪与认识是可检查的内部状态及版本历史，不构成人类主观感受的证明，也没有后台自主生活或自动执行目标。
