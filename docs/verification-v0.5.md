## 已修复的路径与剩余发布条件

- 服务端拆出正文及理由的完整句复核单元，必须逐句覆盖；来源 ID 使用动态枚举并逐提案校验，事务内再次核验原文角色、范围、版本、权限及哈希。
- 情绪方向与当前衰减强度做数值核验。有限词法守卫拦截可定位的条件扩大、限定词丢失和未绑定来源；其否定、假设及改写误拒仍是已知限制，不是完整语义证明。
- 反思请求不再发送派生事件标题、梗概、评分理由或细节解释；完整核验原文仍提供。旧状态只作为背景，缺少旧状态不证明过去从未形成认识。
- 对严格 `retain_turn=false` 且 `actions=[]` 的判断，服务端清除夹带的新经历和状态，仍严格检查其他字段。最后公园诊断定位到错误来自 `memory_clarification`，现已在该分支校验后清除它，由回答直接读取原文。新增回归确认虚构金额不进入实际回答上下文。

**最后这一回答修复尚未经过真实模型复验，v1.5 也未完成全套 12 组成对复验。** [作品公园诊断](verification-v0.5-fiction.json) 的程序检查通过，但独立内容复审失败；[最后纯聊天诊断](verification-v0.5.json) 只支持一个回答问题此次未复现。尚不能据此解除发布阻断。

后续先用保留的失败样本继续改进来源与解释边界，再在新的明确授权额度内复验最后修复及完整成对场景，保留无变化和退化结果。全部语义及确定性门槛通过后才升级生产和启用每日两轮策略；当前没有调用授权余额。

## 复现

顺序执行本地检查，避免多个数据库或云验收并行：

```sh
python3 scripts/manage.py test
python3 -m unittest discover -s scripts -p 'test_reflection_budget.py' -v
python3 scripts/verify_reflection_v5.py
python3 scripts/verify_reflection_upgrade.py
```

默认模拟验收不调用云。真实验收命令在当前额度下会在启动容器前拒绝请求，并保留已有语义报告。`--cumulative-call-limit` 是需要明确授权的全历史总上限，不能按单次运行追加。`--on-only` 仅作开启侧诊断，`--on-only --chat-only` 仅作基线聊天诊断，两者都不是新的成对收益验收。
