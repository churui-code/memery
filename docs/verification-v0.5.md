## 真实模型结果及发布阻断

前两轮使用较早策略，分别消耗 68、74 次请求，共 **142 次**。第一轮仅 4 组机械检查完成；第二轮 11 组完成，但逐例阅读最终状态发现无依据补充过去背景、金额对象混淆、新增目标条件，以及情绪数值升高却声称下降。目标完成场景另有传输超时和对话协议错误。因此两份报告均不能用于通过发布门槛。全部失败和逐例评审保留于 [最新真实报告](verification-v0.5.json) 与 [历史报告目录](verification-history)。

`reflection-v1.2` 增加服务端完整句复核单元、逐句引用覆盖和支持判定；任何句子无依据或冲突均拒绝整轮。情绪变化方向须与冻结的当前衰减强度一致。存储事务独立重验同样条件，失败不写入半轮状态、不消费新材料。新机制的真实模型效果仍待验证，不能根据模拟结果宣称语义问题已经全部消除。

此前验收脚本仅限制单次运行 96 次，未合并重跑额度，导致累计超过用户原定总上限。现已停止额外云调用，新增固定的本地累计账本 `data/qa/reflection-v0.5-budget/ledger.json`：每次请求前加锁、原子预扣并同步落盘，失败和中断不退还，历史按运行身份去重回填。当前 **142／96、剩余 0**；[预算摘要](verification-v0.5-budget.json) 同时保留已知提供商用量，缺失用量不补造。

追加额度须由用户明确批准。脚本的 `--cumulative-call-limit` 表示全历史总上限，不能当作每轮新增额度；若批准追加 96 次，总上限才可设为 238。未获批准时不执行真实验收或启用生产反思。

## 复现

按顺序运行，避免多个数据库或云验收同时执行：

```sh
python3 scripts/manage.py test
python3 -m unittest discover -s scripts -p 'test_reflection_budget.py' -v
python3 scripts/verify_reflection_v5.py
python3 scripts/verify_reflection_upgrade.py
```

真实验收前先检查累计账本及授权额度；默认 `--real-model --local-vectors` 在当前额度下会在启动容器前拒绝请求，并保留现有语义报告。真实对比应逐例记录改善、无变化和退化。安全拒绝且状态完全不变可计为无变化；协议错误、超时、未检查到实际回答上下文仍须保留为未完成。
