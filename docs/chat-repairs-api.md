# 聊天可靠性修复候选：schema 7

本候选保持 MiniMax-M3 配置和默认关闭的反思不变，不自动更新运行中的生产服务。schema 6→7 是增加表/列的迁移；原文不改写、不自动推断历史纠错。旧二进制不支持schema 7，部署前需备份，回退应恢复备份而非运行降级SQL。

记忆控制由现有`MemoryService`承担：查找可用证据、请求模型提案、验证来源及版本、必要时重评、生成回答、事务提交，再返回实际保存状态。模型只有提案权限，不能直接写数据库；操作目标、请求次数、超时和失败处理由程序决定。当前不增加另一模型作记忆审核，语义判断仍需要真实聊天验收；逐字引用正确不等于提案含义一定正确。

独立真实测试已发现模型在明确收到`memory_failure`后仍可能承诺“以后记住”。用户选择继续保留正常聊天回答；响应机器状态和程序提示准确，但正文遵循性仍是已知未通过项，不能把有警告的HTTP 200视作完整验收通过。不会用固定程序回复遮盖该模型失败。

云契约的格式诊断会一次收集最多12项已知字段错误，供仅有的一次重新提案同时修复。诊断不包含错误值、未知字段原名或聊天原文；不会通过移除非法字段或自动修改提案来绕过校验。

可选`experience.time_quote`及事件`time_quote`的精确空字符串兼容为`null`，表示时间未知，不能保留随其附带的模型时间戳。非空时间引文仍严格校验，不以空值兼容为由删除非法日期或跨事件借用日期；其他引文字段不适用此转换。

## 重评失败

`POST /v1/chat` 和实验台聊天端点在**重评来源或格式验证失败**且仍有回答额度时，可以返回HTTP 200、正常回答和：

```json
{
  "memory_status": "failed",
  "history_saved": false,
  "experience_id": null,
  "episode_ids": [],
  "memory_changes": [],
  "self_changes": [],
  "warnings": [{
    "code": "memory_reassessment_failed",
    "message": "本轮记忆整理失败，回答未保存。",
    "diagnostics": [{"code": "extra_forbidden", "path": ["field"]}]
  }]
}
```

服务丢弃本轮全部记忆提案，只使用当前输入和已经验证的已有证据回答；回答开头、网页状态与交互CLI明确提示未保存及本轮变更未提交。实际回答上下文包含`memory_failure`，明确`changes_committed=false`和`history_saved=false`，并要求回答模型不能承诺旧记录作废或以后已按新值记忆，区别于用户主动选择不留存。不会创建本轮聊天、经历、事实、内部状态或复习；调用审计和调度活动时间仍保留。警告诊断仅含受控原因码和字段路径，不保存异常原文或模型输入。常规响应的`warnings=[]`。

仅重评校验或重评结构化响应无效可降级。首次整理的提案未通过来源、格式或目标校验时，整份丢弃，并在剩余额度内最多重新提案一次。原文、已展示证据及权限范围固定，只回传受控原因码和字段路径；新提案从头完整校验，不沿用失败提案字段，不自动扩大原文范围、移除错误子项或从历史授权时间引文。再次无效、证据冲突、删除错误、数据库并发冲突仍返回错误。如果两次整理已用完而需要重评，保留最后一次回答额度并以本轮未保存方式回答。回答超时、额度耗尽或总体超时也不假报成功。每轮最多3次请求，包含内部重试；不增加额外纠错模型请求。

首次整理的云工具按实际展示的`memory_evidence`限定事实操作：列表为空时只允许`create`且不能带目标；存在事实时`update/forget`的目标只能选择这些独立事实ID。事件ID不能用于事实更新，事件纠错使用`corrections`。提供商未遵循这些枚举时，服务端拒绝整份提案，并只在剩余额度内重新提案一次，不擅自移除错误操作后部分提交。上下文估算与实际请求使用同一份动态工具协议。

重评的事件追加目标也按最终证据限定，排除本轮已固定的纠错目标；纠错证据应新建事件。最终重评同时校验固定纠错与新事件提案，若同一目标既纠错又追加，整轮按重评失败降级。持久化入口再次拒绝这种组合，避免错误提案到事务提交时才暴露为通用异常。

## 事件细节纠错

模型整理工具新增`corrections`，不是客户端可直接写数据库的接口。本地内部格式包含`target_id`（事件ID）、`expected_revision`、`experience_id`、`start/end`（Python字符偏移，半开区间）和当前用户逐字`quote`；旧格式保持兼容。

云端工具只接受`detail_ref`、`old_quote`和当前`quote_refs`，拒绝同时提交目标ID或坐标。`detail_ref`从本轮实际发送的冻结证据表`correction_targets`选择，例如`c0001`；程序仅用该表还原原有事件ID、版本、来源ID和完整细节范围，不查询数据库补找未展示内容。该表只列云端可见的用户细节，排除助手内容及legacy投影，重提沿用同一证据映射，并计入完整请求预算。`old_quote`是选中旧detail里唯一的错误主张子串；服务端据此收窄旧范围。当前`quote_refs`仍严格还原当前用户原话。旧父范围必须完整对应已展示的用户细节，子范围不得越界；提交时再核对版本、范围、权限及是否已被替代。允许同一来源的多个不重复细节，拒绝同时追加和纠正同一事件。重提类型新增correction，仍要求用户逐字来源和已展示事件ID。

事务保存`episode_corrections`关系（只含ID、版本、偏移和时间），引用本轮完整纠正经历。旧原文仍可用经历ID本地查看；有效事件视图排除错误范围，覆盖它的摘要重建；以原始逗号、分号或句号等分句界限保留完整未受影响片段，无法安全拆分的片段不作为当前证据。删除纠正经历不会重新激活被否定的旧证据，删除账本重放也保留这一性质。

同轮事实更新与事件纠错在事务锁内先验证来源、版本及原先有效的事件，再进行事实失效与范围替代；仅重建这些先前有效的用户原文事件，不重新激活原先已失效记录。被影响的独立用户原话可继续使用，但旧解释性元数据和整段历史退出上下文。当前检索将已选中事件的原文片段交给统一预算装配，不再按金额、原话或动作关键词分类、隐藏细节，也不设每事件4/8条细节上限；预算不足时明确省略完整事件。展示证据仍不自动授予纠错或合并事件权限。

`experiences.correction_history_blocked`阻止旧整段回答/历史再次进入云上下文；独立用户证据仍可按事件读取。依赖错误来源的内部解释失效，旧向量任务取消，事件版本更新并重新索引。后台索引尚未完成时，原文范围过滤同样生效。纠错与原事件使用显式关联，后续仍可从原地点检索到简短纠错；连续纠错沿同一已定位事件的来源关联到最新证据。同一批重叠纠错拒绝提交。真实偏好演变继续使用`evolution`，不撤销过去事实。

响应新增`episode_corrections`（默认空数组）；有事件纠错提交时`memory_status=committed`，即使未修改独立事实。

## 当次要求与长期偏好

整理工具对长期`preference/instruction`新增`durability_quote`，必须逐字来自本条当前依据，说明持续适用。缺少持续依据的提案跳过，不导致整轮失败；任务本身仍可作为经历保存。明确要求遗忘不受此新增门槛影响。直接`/v1/memories`手工保存接口不变。

“这次起名轻松一点”不应变成长期画像；“以后给我起名都用轻松直白的风格”可以保存。持续性的语义判断仍由模型完成，本地只验证逐字来源，不能把来源匹配当作语义正确的充分证明。

## 验证方式

隔离数据库运行 `python -m pytest -q tests`，网页状态运行 `node --test tests/test_chat_ui.cjs`。迁移、并发冲突、未索引纠错、独立相似事件、删除重放以及降级失败路径有专门回归。

`scripts/verify_chat_repairs.py`在临时HTTP实验服务上使用全新合成故事；原脚本和30次账本保持不变，客户端最多10轮，禁止自动重跑同一结果目录。不得指向或重置冻结反思验收账本。本轮独立验收由单独GPT-6/high对话负责，使用`scripts/verify_independent_acceptance.py`及另一份累计账本；最初授权60次，用户随后明确取消该新增总上限。账本保留授权变更和全部已有请求，不按重跑清零，每轮3次请求与整体超时继续生效。具体结果包含失败记录，另见各批独立验收报告。
