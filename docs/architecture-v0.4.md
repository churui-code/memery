# v0.4：事件记忆、线索唤醒与可检查的上下文

本文描述当前代码的机制与约束，不是验收通过声明。实测结果应查看对应验证报告，不能用合成夹具、模拟模型或理论公式代替真实模型表现。

## 1. 设计目标与数据层次

原始经历长期保留；随时间改变的是被唤起的概率、此次展开的细节和当前情绪强度。原文不会因为进入远期记忆而被反复摘要覆盖。明确删除、隐私撤回及其依赖传播仍然生效。

系统继续使用 Python/FastAPI、PostgreSQL 16 与 pgvector。数据库既保存原始证据，也保存可重建的事件和索引；检索、上下文组装、模型提案与提交分开处理。

| 层次 | 主要数据 | 职责 |
| --- | --- | --- |
| 原始经历 | `experiences` | 保存成功且允许留存的一轮用户原文与助手回复、记录时间、来源性质、修订号和源哈希；不受聊天窗口保留期影响 |
| 当前会话窗口 | `messages` | 为近期连续对话提供完整发言；默认 30 天保留，过期不删除原始经历 |
| 事实与修订 | `memories`、`events`、`memory_evidence` | 保留独立事实、偏好、有效期及纠正历史；原有 `events` 是事实审计表，不表示生活事件 |
| 生活事件 | `episodes`、`episode_versions` | 一轮可以包含多个事件，一个事件可接收明确的后续补充；保存梗概、重要性及理由、情绪意义及理由、参与者与版本 |
| 精确证据 | `episode_evidence`、`episode_details` | 用原始记录 ID、角色、Unicode 字符起止位置、源版本和哈希定位原话；话语、动作、金额等细节各自有权重 |
| 唤醒入口 | `episode_cues`、`episode_associations` | 索引人物、地点、物件、独特短语等线索，以及事件之间的有限联想 |
| 自我状态 | `self_observations` | 版本化的情绪、关系理解、身份认识、信念和目标；每项有原因、置信度和来源 |
| 工作与审计 | `episode_jobs`、`episode_chunks`、`episode_rehearsals`、`model_calls` | 异步向量、有效重提时间及模型各阶段来源清单、token 用量和状态 |

`recorded_at` 表示记录进入系统的时间；事件的 `occurred_at` / `occurred_until` 表示原话支持的发生时间区间，结束时间不包含在内。`time_precision` 为 `day`、`range` 或 `unknown`。服务端从完整年月日或明确的今天/昨天等日级线索确定区间；只有日期时规范到上海时区日首与次日日首，不接受模型补出的中午或秒级时刻。两个有明确连接词的完整日期可以构成范围；缺少年份、模糊年份、未完整描述的范围或无时间含义的引文保持 `unknown`、结构化时间为空，原始 `time_quote` 仍保留。跨轮补充的每个细节还带 `source_recorded_at`，便于区分较早陈述与后来补充。

新写入原始归档的衍生时间元数据同样经过这一归一化，旧接口中的 `occurred_at` 至多保存已确认区间的起点。当前数值化时间索引支持日和明确日期范围；原话中的小时、分钟等细时刻保留在引文中，尚未形成更精细的数值索引。既有历史归档的时间字段不会被迁移追溯改写。

`context_type` 区分普通对话、用户转述、假设、作品。助手说过某句话，只能证明说过，不能自动成为外部事实。摘要、线索含义和自我认识是解释性数据，精确细节以可定位原文为依据。

事件和细节分别持久化服务端生成的 `source_reliability`，包含 `quote_verified`、`speaker` 和 `claim`；当前分类为 `reported_unverified`、`fiction`、`hypothetical`、`conversation_only`。`quote_verified=true` 只确认引用能定位于原文，不证明所述事件在现实中发生。该分类不是由模型给出的真实性概率，也不会从重要性或情绪强度推导。记录同时带 `encoding_version`：结构化事件为 `episode-encoding-v1`，本地兼容表示为 `legacy-local-v1`；来源分类自身版本为 `source-reliability-v1`。

## 2. 写入、来源与删除

模型返回结构化提案，应用验证后才可提交。M3 工具 schema 会内联本地引用以避免遗漏必填字段；工具只要求逐字时间引文，结构化日期由服务端生成。无时间依据的模型时间戳归为未知，不作为事实保存。

云端 `intake` 和 `reassessment` 阶段的 `current_question` 是服务端生成的完整连续句/行单元数组，每项为 `{id,start,end,text}`。`start/end` 是当前完整用户输入的 Unicode 字符位置，结束位置不包含在内；按顺序连接所有 `text`，必须逐字等于完整输入，包括空白、标点和换行。最多 64 组；超过 64 个句/行单元时，合并相邻的完整单元以减少定位元数据开销，不删字、不把长句硬截断。没有句界的长段仍完整传递。这一转换只影响结构化模型请求：客户端仍发送字符串 `text`，回答阶段的 `current_question` 仍是完整字符串。

模型可为需要引用的字段返回 `quote_refs`，选择当前输入中严格递增、有序的单元 ID，由服务端取首末单元之间的完整连续原文（包含中间未列出的单元），逐字还原 `quote`，并计算重复引文的准确 `occurrence`。使用引用时省略手抄的 `quote/occurrence`；短引用仍兼容直接填写逐字 `quote`。未知 ID、乱序、重复引用及与显式引文或出现次数冲突的内容会被拒绝，不能通过引用改写原文或引用其他轮次。事件顶层还原后的 `quote` 是事件的连续证据范围；细节、线索和时间引文都必须位于该范围内。直接提供事件引文时，`occurrence` 从 0 开始，按完整当前用户原文计数。

事件默认重要性为 0.2、情绪意义为 0。偏离默认的重要性和非零情绪意义必须提供非空理由。细节也分别保存理由；未单独给理由时可用该细节的非空 `meaning` 作为解释依据。两者都不等于事实可靠度；重要而感人的记忆仍可能有歧义。

一次成功回复在同一事务内提交事实操作、原始经历、事件投影、自我更新、有效重提和消息。未完成回答、提案无效、来源已经变化或事务失败时，不确认保存部分结果。明确不留存或执行遗忘的那一轮，不再次保存可能重复被遗忘内容的原文。

未返回事件提案时，应用在本地建立保守的事件表示：保留完整来源及完整句子，不自动赋予强烈情绪。原始来源哈希为 `SHA256(UTF8(user_text + U+001F + assistant_text))`；事件投影另有包含来源 ID、版本、哈希及引文的组合哈希。

两种关系有不同用途：

- `context_links` 保存真实内容依赖。它覆盖事实、原始经历、事件和自我状态，供纠正、撤云、删除递归传播；只保存 ID，不保存正文。
- `episode_associations` 保存联想。相同的人物、地点、物件或短语可建立关联，但这些边不传播内容删除。忘记公园里的某件事，不会仅因共享地点而删除所有公园经历。

来源删除会擦除相关原文、事件正文、版本摘要、细节、线索、向量和衍生自我内容，并取消任务。来源撤云使相关事件不能进入云端上下文。纠正使旧解释失效、相关经历标记陈旧；明确的事实演变可以保留旧经历作为历史，但仍撤销需要重评的内部解释。

当前删除依赖有意保守：原始归档是一整轮用户发言和助手回复，且记录本轮模型实际见过的来源。删除一个来源可能擦除整轮衍生记录中的其他内容。v0.4 没有宣称已完成角色或字符跨度级的精细隐私保留。事件接口只读，明确遗忘仍通过原始经历或既有事实/会话删除入口执行。

## 3. 时间、版本与后台任务

数据库当前 schema 版本为 5。`migration_004.sql` 建立事件、证据、线索、关联和任务等结构；增量迁移 `migration_005.sql` 为 `model_calls` 增加可空的 `estimator_version` 审计列，保留既有记录。旧调用未记录该版本时保持 `NULL`，不推造历史估算器版本。应用版本仍为 `0.4.0`；原文单元与 `quote_refs` 是模型请求和提案绑定机制，不要求迁移重写原文。

`Repository(settings, clock=None)` 默认使用真实 UTC 时间。实验使用 `MutableClock` 注入逻辑时间，拒绝无时区时间和倒退；事实有效期、经历时间、情绪计算、有效重提和聊天窗口保留规则都使用该时钟。

数据库任务租约、重试和服务整体期限使用真实时间，不会因为实验直接推进一年而让工作进程错误地过期。事件索引租约为 120 秒，失败默认 10 秒后重试，累计 3 次失败后标记失败。

事件后续补充保留原始证据，增加事件版本并生成新投影哈希；旧事件解释所派生的自我状态失效。索引任务绑定事件 ID、版本、源哈希及租约 token；完成前再次核对这些值和删除/陈旧状态。旧 worker 不能覆盖新版本或恢复已删除内容。

同一会话使用数据库 advisory lock，内容变更使用全局 epoch 防止生成过程中删改来源后仍提交旧回答。新增归档不必使其他纯读取对话全部冲突；修改已有事件、事实和自我解释时会更新相关一致性状态。

## 4. 四路召回与逐级展开

检索先产生有界候选，再计算当下活跃度。存入数据库不代表原文始终进入模型上下文。

| 路径 | 当前实现 |
| --- | --- |
| 关键词与线索 | 中文分词全文索引，另做原文有据的线索匹配；线索频率在可见、未删除、非陈旧事件中计数 |
| 语义 | 本地 BGE 512 维向量，事件 chunk 使用 HNSW；可用精确扫描做对照；嵌入不可用时保留其他路径 |
| 时间与近期 | `recorded_at` / 发生时间区间条件和近期候选；范围按重叠关系匹配；“今天/昨天/前天”按上海时区、逻辑当前时间构造两种时间查询 |
| 一跳联想 | 从已达到条件的前 8 个种子向外最多取 20 个相关事件；关联事件仍需匹配当前问题，不仅因共享地点就唤起 |

自然模式默认主候选最多 80 个，深度模式扩大至 160 个（策略上限 320），最终激活最多 12 个。模型可提出最多 4 个补充索引查询；补充查询本身不重复调用嵌入模型。限制了会话范围的直接检索不进行跨会话联想扩展。

当前策略版本为 `episodic-activation-v1`。活跃度是一套待实测校准的工程规则，不是人脑记忆公式：

```text
I = 重要性，E = 情绪意义
age = 距记录时间或最近有效重提时间的天数，取较近者
half_life = 7 + 358 × I² 天
base = 2 ^ (-age / half_life)
score = 0.50 × relevance + 0.30 × base + 0.12 × I + 0.08 × E
```

`relevance` 综合词面重合、语义相似度和线索强度；高频共享线索降低独特性。当前语义归一化使用 `(similarity - 0.42) / 0.43` 后限制在 0～1，随后乘 0.85；它与候选最小相似度设置是两处参数，修改一处不自动改变另一处。

在可见库只出现于一个事件、长度至少 3 个字符、且完整出现在当前查询中的线索，可把该事件得分提升到至少 `0.82 + 0.1 × I`。所以久远的重要事件可能由一个独特词唤醒，普通往事通常需要更充分的组合线索。自然模式门槛为 0.36，深度模式为 0.14；非空查询还要求相关性大于 0.08。一次关联最多增加 0.08 分，并保留来源事件身份。

展开层次为 `hint`（提示）、`gist`（梗概）、`anchor`（关键原话）、`fragment`（当前问题所需片段）。自然/深度模式每件事分别最多选择 4/8 个细节。金额默认不主动展开，询问金额时才优先呈现；询问原话或动作时同样针对所需细节选取。未被模型抽取的细节仍可从事件原始证据中按当前线索展开完整句子，附原文位置，不能补写没有记载的内容。

多件相似事件接近同一得分且没有独特入口时，结果携带歧义标记，不能把两天的动作、费用和人物拼为一次经历。没有检索到表示本次未找到，不表示确定从未发生。

## 5. 活跃度、情绪与有效重提

三类值分别处理：

- 事件的长期重要性/情绪意义描述这段经历为什么值得保留，普通检索不会自行提高它们。
- 事件当下活跃度按查询、时间、线索和有效重提即时计算，不定时修改原文或每日扣减一列分数。
- 自我状态中的当前情绪强度按 `intensity × 2^(-elapsed / half_life_hours)` 衰减；历史强度和原因保持原样。关系、信念、身份、目标没有套用这条情绪衰减公式。

有效重提需要当前用户的原文依据、实际提供过的事件，以及一次成功提交的回答。形式包括讨论、确认和补充；同一事件 24 小时内不重复强化。候选召回、预览、助手自行复述或查看实验报告不构成有效重提。

自我更新只允许引用本轮实际呈现的经历/事件。结构化阶段必须显式考虑 self_updates（无变化则空列表），它与用户个人事实提炼分开；对作品的实际讨论可以形成自己的观点，讨论事件为 conversation，作品中的情节仍为 fiction，不能因主题相同合并。删除或更新证据会使旧内部解释失效；删除最新版本也不会自动复活更早版本。软件可以维护连贯的自我状态和表达，但这些状态不证明主观意识或人类式感受。本版没有后台自主生活、主动目标执行或云端周期反思。

## 6. 上下文预算、重评与提交

`ContextComposer` 对系统说明、工具及结构化 schema、当前输入、计划变更、近期对话、事实、自我状态、事件证据统一计费。默认配置为 24,000 个估算输入 token，预留 20%，有效预算 19,200。估算器版本仍为 `utf8-half-v1`，使用序列化 UTF-8 字节数除以 2 向上取整；它可复现，但不是 M3 的真实 tokenizer，提供方返回的 usage 单独记录。估算对象是实际发送的请求 payload，包含结构化阶段的原文单元 ID、位置、文本、JSON 结构与转义开销，以及工具 schema 和协议字段，不能只计算用户字符串或正文长度。

当前输入及必要说明必须完整保留；必要部分已超预算时返回 413。 当前话题明确相关的内部状态优先于普通回忆与历史，防止已形成的观点被大量候选挤掉；明确被问及的金额、动作或原话证据仍优先。相关性由本地中文分词匹配判定，过滤“观点、看法、讨论”等空泛词，不因泛称“你的看法”就提升所有状态。可选内容按近期上下文和相关性装入；发言组、事实、自我解释、精确引用均作为完整单元处理。事件可减少可选细节或退到梗概/提示，明确请求的精确细节不能截断成半句；装不下的事件会被整体省略并记录原因。通过来源 ID、角色、版本和跨度消除重复信息；同一事件内已被完整父片段覆盖的引用合并，重复发生位置不会混并。统一成本函数直接估算实际提供方请求（包括工具协议和嵌套 JSON 转义），在选择可选内容时就使用该成本；冻结最终证据前按回答与必要重评两种请求的较大成本预留空间。

正常自动记忆流程为：初次召回 → `intake` 整理提案 → 必要的本地补充检索 → 组装最终证据 → 条件性 `reassessment` → `answer` → 原子提交。

来源 manifest 记录 ID、版本、展开层次、原文跨度及内容哈希。初次和最终 manifest 不同时，重评只允许调整经历、事件、自我更新和有效重提，不能改掉已确定的事实操作、遗忘或不留存决定；发现矛盾可以返回冲突。即使不需要重评，也会再次按最终呈现来源校验提案。

首次判断与回答阶段的瞬时网络故障或不完整工具协议可重试一次，失败调用也保留在调用清单；本地引文/来源校验失败、证据冲突、权限变化、限流和重评失败均不重试。重试必须为后续回答留出请求额度；若重试后还需要重评而额度不足，则明确失败且不提交。

每轮最多 3 次模型请求，默认整体期限 240 秒；单次模型请求默认 90 秒且受剩余整体时间约束，同一进程最多同时处理 3 个聊天请求。每阶段记录状态、实际曝光来源清单、估算输入、估算器版本、策略版本和提供方 usage，不记录提示正文。回答生成完成与事务提交成功分别记录；没有完成事务不确认记忆保存。

## 7. 接口、实验与当前限制

新增只读接口为 `GET /v1/episodes`、`GET /v1/episodes/{id}`、`POST /v1/recall/preview`；`POST /v1/chat` 增加 `recall_mode=natural|deep`。预览返回候选、分数分量、入选原因、展开层次、证据、manifest、预算及省略原因；它不调用语言模型、不写记忆，但查询时可以运行本地嵌入。

实验台由 `MEMORY_LAB=true` 启用，默认关闭。独立启动方案使用 `compose.lab.yaml`、单独端口与数据目录。每个实验还有独立 schema、删除账本和可持久化逻辑时钟；`/lab` 提供界面，数据操作通过鉴权的 `/v1/lab/*`。实验可选择 mock/live 模型、fake/local 嵌入；这些模式必须在结果中明确标注。快照、时间推进、批量探测不应改正式记忆。

主要默认配置：

| 项目 | 默认值与边界 |
| --- | --- |
| 模型 | MiniMax-M3，结构化整理最多 24 个事件、12 个自我更新、12 个有效重提 |
| 嵌入 | `BAAI/bge-small-zh-v1.5`，512 维；经历/事件候选阈值默认 0.42 |
| 上下文 | `CONTEXT_BUDGET_TOKENS=24000`，配置范围 1000～100000 |
