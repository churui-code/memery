# schema 5 → 6 与 v0.5 上线

v0.4 已提交并推送，基线 SHA 为 `070f5cab81e226303c164619ef8069f15b468480`。保留 v0.4 镜像、配置和加密备份，新增开发在独立分支完成。

## 数据变化

增量迁移 `006` 新增反思设置、运行、真实日配额和事件处理水位。`self_observations` 追加生成来源、运行关联和证据定位，既有记录按对话生成保留；`model_calls` 增加独立反思运行关联，允许反思调用不携带会话 ID。事件追加经过验证的纠错触发标记。

不批量发送历史内容到云端，不改写原始双方发言或既有状态版本。新安装自动开关为关闭。已有实验按需迁移各自独立 schema，旧实验缺少反思配置时视为关闭。

## 发布步骤

1. 在隔离 schema 中运行完整回归、成对模拟、真实向量和真实模型验收；保留失败记录。检查无错误来源、无越权、无半轮提交。
2. 记录当前原文行数及规范化哈希，创建加密升级前备份，保留 v0.4 镜像及 Compose 配置。
3. 暂停旧 API 和 worker。运行迁移、删除账本重放及租约清理，再核验原文行数与哈希。删除重放测试须使用升级前含删除对象的隔离备份，不能用空数据库替代。
4. 启动 v0.5 API、worker、reflector 与独立实验台，核验生产未注册实验接口、实验无法访问生产、自动反思仍关闭。
5. 验收通过后，按本项目已批准策略通过 `PATCH /v1/reflection/settings` 设置 `enabled:true`。代码和新安装默认仍关闭。

## 恢复与失败处理

`scripts/manage.py restore` 在隔离临时库中解密导入、迁移、重放独立删除账本并清理未完成反思。切换期间停掉 API、worker 和 reflector；运行记录、每日已用配额保留，旧租约不可继续，自动反思暂停。验证完成后才能恢复调度。

停写后还会从当前库导出真实日配额，并与恢复库按日期、轮数和调用数分别取较大值；失败请求已经占用的额度也不会因恢复较旧快照而退回。schema 5 的配额导出明确为空，不能将缺失或损坏的 schema 6 配额表当成未使用额度。

可复现的离线升级演练使用 `python3 scripts/verify_reflection_upgrade.py`。先保留本机 `home-memory:0.4` 并构建待验收的 `home-memory:0.5`；脚本不会拉取、构建镜像或调用云模型。它以现有镜像 ID 固定两个版本，在独立 Compose 项目 `home-memory-v05-upgrade` 的内部网络中，使用独立数据库、密钥和删除账本：由 v0.4 保存非空合成事实及依赖的原始经历、事件和自我状态，生成加密 schema 5 备份，再用 v0.5 解密、迁移和核对既有列的行数与 SHA-256。随后验证删除来源后恢复旧备份不会复活依赖内容，并验证 v6 排队/运行快照的租约清理、默认停用和失败调用配额保留。演练只启动数据库和一次性 Python 容器，不启动 API、worker 或 reflector，也不连接生产库。成功或失败均写入 `docs/verification-v0.5-upgrade.json` 及 `docs/verification-history/`；结束时执行隔离项目的 `down`，将数据库、账本、密钥和加密备份保留在忽略目录 `data/qa/reflection-upgrade-<运行ID>/`。与其他验证脚本顺序运行。

不要通过 schema 降级删除新表。若必须回退应用，先停掉三类进程，使用升级前加密备份与完整最新删除账本恢复到隔离库并验证，再使用保留的 v0.4 镜像及配置。未升级的 v0.4 应用不应连接 schema 6。原文恢复不应撤销任何已记录删除。

生产升级结果、备份位置、原文一致性哈希与验证时间写入版本化部署报告；运行数据、密钥和加密备份留在忽略目录，不提交 Git。
